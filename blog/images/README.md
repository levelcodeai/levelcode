# Blog images — capture checklist

Drop the captured assets here with these exact filenames so the post resolves them.

| File | Type | What to capture | Notes |
| --- | --- | --- | --- |
| `hot-reload-hero.gif` | GIF (loop) | Split view: `extension.js` + status bar. Edit `item.text`, save, status bar updates live. Repeat 2–3 times. | The hero. ~6–10s, ~1200px wide, looping. |
| `generate-package-palette.png` | PNG | Command palette showing **Atom++: Generate Package…**, or the name input with `hello-atom` typed. | Crop to palette + a little editor. |
| `dev-status-bar.png` | PNG | Status bar close-up: `● dev: hello-atom` next to `🚀 hello-atom`. | Tight horizontal crop of just the status bar. |
| `save-to-update.gif` | GIF (loop) | Close-up of editing `item.text` → `⌘S` → status item swaps text instantly. | The core "wow". ~4–6s, focused on code + status bar. |
| `reload-error.png` | PNG | Deliberate typo → save → error toast + **Atom++ Packages** output channel stack trace. | Optional; shows the editor survives a bad edit. |

## Tips
- Record GIFs at the same window size for visual consistency; keep them short and looping.
- Use the **Atom++ One Dark** theme in the captures so the post matches the product.
- For crisp text, capture on a Retina display and export at 2×, then size down in the post if needed.
- Tools: macOS screen recording (⇧⌘5) → convert to GIF (e.g. Gifski), or a recorder like Kap.
